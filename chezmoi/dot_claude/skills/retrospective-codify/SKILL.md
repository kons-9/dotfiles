# Retrospective Codify

タスク終了間際に「最初に知っていればこうはならなかった」知見を抽出し、再現可能な形に固定する。

## いつ使うか

- 試行錯誤の末に解決した（最初の試みが失敗した、間違った仮説を立てた、ドキュメント不足で時間を消費した）
- 同様のタスクを将来また行う可能性がある
- ユーザーが「教訓を残して」「ルール化して」と言った

使わない場合:
- 一発で通ったシンプルなタスク（抽出すべきものがない）
- プロジェクト固有の一回限りの対処（コミットメッセージで十分）

## ワークフロー

1. **失敗と成功を対にする**: 現タスクから以下の3点を書き出す
   - 最初の試み（何をした / どう失敗した）
   - 最終的な解決策（何がうまくいった）
   - 橋渡しとなった知見（なぜ最初の試みではたどり着けなかったか）

2. **「最初に知るべきだったこと」を言語化**: 知見を1〜3文で要約。回顧ではなく未来の自分への指示として書く（命令形: 「Xをするな」「先にYを確認しろ」）

3. **分類**: 以下の決定表に従って出力先を決定

| 判断軸 | 出力先 | 例 |
|---|---|---|
| 短い、常時適用、判断不要 | `CLAUDE.md`（グローバル / プロジェクト） | 「pnpm は v10 以上を使う」 |
| 手順・判断・テンプレートが必要 | 新規 skill or 既存 skill に追記 | 「MoonBit の C バインディング手順」 |
| プロジェクト固有の一回限り | 採用しない（コミットメッセージで十分） | — |

4. **重複チェック（必須）**: 提案前に既存の知識と照合する
   ```
   # CLAUDE.md の重複
   grep "<キーワード>" ~/.claude/CLAUDE.md
   grep "<キーワード>" <project-root>/CLAUDE.md

   # skill の重複
   ls ~/.claude/skills/
   grep "<キーワード>" ~/.claude/skills/*/SKILL.md
   ```

5. **提示**: ユーザーに以下の形式で提示する
6. **書き出し**: ユーザーの採用指示を待ってから書き出す。承認なしに変更しない

## 提示フォーマット

```
## 振り返り

### 教訓 1: <短いラベル>
- 最初の失敗: <1行>
- 最終的な解決策: <1行>
- 知見: <1行>

## 提案

採用候補:
- [rule] CLAUDE.md: <1行> (教訓 N より)
- [skill append] <既存 skill 名>: <1行> (教訓 N より)
- [skill new] <skill 名>: <1行> (教訓 N より)

重複検出（提案不要）:
- <教訓 N>: 既存の <skill/rule 名> の <セクション名> で完全にカバー済み

不採用:
- <教訓 N>: <不採用理由>

採用する項目を番号または項目名で指示してください。提案ゼロも正しい結論です。
```

## レッドフラグ

| 浮かぶ合理化 | 現実 |
|---|---|
| 「プロジェクト固有だけど念のため skill にしよう」 | skill が肥大化して検索性が下がる。コミットメッセージで十分 |
| 「承認を飛ばして先に書いてしまおう」 | CLAUDE.md / skill を勝手に変更すると将来の挙動が予測不能になる。必ず 提案 → 承認 → 書き出し |
| 「知見が薄いが何か書かないと」 | 提案ゼロも正しい回答。空の振り返りは害がない |
| 「重複チェックは面倒だから飛ばそう」 | 重複ルールが残ると挙動が分裂する。重複チェックは必須ステップ |
